# 更新记录 - v0.9.0（熟练度 · 双变数 · 白板 100 量纲 · 25 技能重做）

- 日期：2026-08-22
- 类型：feat（含 breaking 数值/规则变更）
- 提交：见 Git 节

## 变更内容

### 1. 熟练度系统（触发概率个性化）

- 每个技能实例附带 **熟练度（0~100，高斯抽样、集中于 50）**，按技能各自的
  `mastery: [lo, hi]` 区间换算倍率，缩放触发概率（卡牌技能名行显示
  「熟练度 63：触发率 ×121.00%」）；
- 每个技能的熟练度区间互不相同（重击 ×0.55–1.65 波动最大、雷罚/大器晚成
  ×0.85–1.15 最稳）；条件触发型技能改为缩放效果值（背水一战 value、
  坚守壁垒 immune）；
- 取代 v0.8 的 chance 高斯扰动（`md5_variance.chance` 已删除）。

### 2. 双变数共鸣（每技能两个变数槽位）

- 每个效果类型在 `variable_link.targets` 声明 1~2 个可共鸣字段，对应技能中
  **两个不同的数值**；每个槽位独立以 **25%** 概率实际成为变数
  （技能级出现率 ≈ 44%，双变数率 ≈ 6%，实测 40.5% / 7.2%）；
- 模式重划：own 10 : enemy 3 : difference 2 : sum 1——**单值占绝对多数、己方优先**
  （v0.8 的 source/mode 权重合并为 mode_weights，新增 sum 并值模式）；
- 公式括号**紧跟对应数值**（不再统一放句尾）：「提升至 452.65%
  （299.07% + ⚔️*1.54%）」；变量式以属性 emoji 表示，own 省略范围词、
  enemy 前缀「对方」、差值/并值用【己方-对方】/【己方+对方】；
  连接符改为 `*`；**去掉「当前」措辞**；尾句依赖描述用属性全名；
- 实时技能数据升级为**多占位**：`live_text` 中每个变数位为 `\u0001` 标记
  （至多 2 个），`link_calc` 变为列表，前端按标记顺序逐个重算
  （与引擎逐点一致，有测试保障）。

### 3. 白板 100 量纲（数值实际不变）

- hp/atk/def/spd 基础值统一为 **100**（称号/加成下可超 100）；
  crit/dodge 仍为百分数；
- 战斗折算常数：`atk_factor` 0.13、`defense_factor` 0.05、`gauge_threshold`
  1000（速度 100 ≈ 旧速度 10 的出手节奏）——伤害、节奏与旧体系等价；
- 称号加成等比换算（攻/防 ×8、速 ×10，HP 与百分比项不变）；
  技能面板数值同步换算（破甲 34、行动槽 260/450、大器晚成 +3.0 等）；
  战力权重调整为 hp 1 / atk 0.5 / def 0.3 / spd 0.2（白板战力 ≈ 244，与旧 231 持平）。

### 4. 属性 emoji 图标

- 每个属性一个 emoji：❤️生命 ⚔️攻击 🛡️防御 💨速度 🎯暴击 🌀闪避
  （locale `attributes.json` 新增 `emoji` 字段）；
- 卡牌属性行显示 emoji+名称，HUD 显示 emoji+数值（悬停显示全名），
  技能公式中以 emoji 简化表示。

### 6. 引擎与持续状态

- **刻为期**：中毒/流血/眩晕/破甲/回春/怨念层/锻痕层均按刻到期（v0.8 的
  「受方行动递减」废除）；毒/流血伤害仍在拥有者行动时结算；
- 行动顺序重排：斩断打断 → 毒发 → 流血 → 行动开始技能（血契/回春/净化）→
  眩晕 → 背水一战 → 攻击；行动后结算大器晚成/嗜血递减/血契转化；
- 新事件模板 25 个（蓄力/雷罚/斩断/不屈/净化/免疫/锻痕/怨念/血契等）；
  buff 集合更新为 16 种（新增 charge/guard/regen/lifesteal/will 等）；
- 快照新增 `gauge_gain`（每刻行动槽推进百分比，前端逐刻动画用）。

### 7. 前端

- 实时刷新支持**多个占位标记**（`fillLiveText` 按序填充）；
  行动槽动画改用 `gauge_gain`（适配 1000 阈值）；
- 技能卡新增熟练度行（名称行右侧 + 悬停）；属性 emoji（卡牌/HUD）；
  其余（简易模式、语言切换、回放控制）不变。

## 动机

用户 v0.9.0 需求：① 每技能两个变数 + 一个熟练度（熟练度影响触发概率、各技能
映射不同），变数出现概率降为 25%，括号紧跟对应数值；② 属性 emoji 图标、
简化描述，变数模式偏向我方单值；③ 数值缩放为白板 100 基准（实际不变）；
④ 20+ 技能重做（见上表）并保持平衡、加大方差提升娱乐性。

## 对确定性的影响

- **breaking**（同名结果改变，属预期）：
  - 技能池 27 → 25、参数全面重做、称号 bonus 换算、属性 base 改 100 →
    **派生流与个性化流全部改变**（同名斗士的技能/数值/描述与 v0.8 不同）；
  - 个性化消耗顺序变更（熟练度取代 chance 扰动、双变数槽位）；
  - 引擎行动顺序与持续状态语义变更（刻为期）→ 同名对战过程与胜负改变。
- 不变的部分：确定性机制本身（种子派生、splitmix64、跨进程一致、顺序无关、
  镜像对战）、功能-文案解耦、展示精度契约、实时数据与引擎一致性契约
  （均有测试覆盖）。

## 验证

- `python -m unittest discover -s tests -v`：**50/50 通过**（新增熟练度契约、
  变数出现率 25% 契约、白板基准、双变数 live 一致性、gauge_gain 快照等测试）；
- 平衡：`python tools/balance_check.py 400 6000`（固定种子 DetRng(20260822)）——
  **25 技能持有者胜率 46.0%–56.2%**（5 轮调参；初版撕裂 71.3% 系流血量纲
  bug，已修复）；
- HTTP 冒烟：/api/health（v0.9.0）、/api/fighter（zh/en）、/api/battle、
  /api/battle/fast 全部正常；
- GUI 黑盒（浏览器）：卡牌显示 emoji 属性 + 熟练度行 + 双变数公式
  （含【己方+对方】并值与对方⚔️敌方向实例）；对战回放中雷罚实时值随破甲
  从 36.80% 降至 28.73%（与引擎共鸣事件一致）；简易模式隐藏公式且实时值保持；
  结果汇总整数伤害；HUD emoji 图标 + 悬停全名。
