- 提交：`<见 git log>`

## 变更内容

1. **tick 行动条战斗系统（需求 2）**：取消"回合"概念，战斗以 tick 推进--
   每个 tick 双方行动槽（gauge）累加自身速度值，达到阈值（`battle.json` 的
   `gauge_threshold`，默认 100）即可行动一次并扣回阈值。**速度决定出手频率**
   （速度 12 ≈ 每 9 tick 一次，速度 9 ≈ 每 12 tick 一次），同 tick 双方可行动时按
   gauge 余量与内部序依次执行。`max_rounds` 由 `max_ticks`（默认 600）取代，
   战报以「第 N 刻」标记 tick，超时判定规则不变。
2. **战斗实时 HUD（需求 1）**：每条战报事件附带双方状态快照
   `{hp, max_hp, atk, def, spd, gauge%, buffs[]}`；前端战斗面板新增双面 HUD--
   HP 条（带数值）、攻击/防御/速度实时值（背水一战触发时攻击高亮）、行动槽进度条、
   buff 徽章（中毒含剩余次数、眩晕、背水一战、会心/轻灵常驻被动），随战报逐条回放
   实时刷新。
3. **技能 MD5 个性化（需求 3）**：每个技能的触发概率与数值以
   `md5(规范化名字 + ":" + 技能id)` 为独立种子做确定性扰动（倍率区间
   `skills.json` 的 `md5_variance`：chance ×0.7–1.35、value ×0.85–1.25）。
   同名技能在不同名字手中数值不同（如「心眼」在赵子龙手中暴击 +10.4，
   在吕布手中 +9.1）；斗士卡牌技能条直接展示个性化后的实际数值
   （触发率 39% · 毒伤 2/次 · 持续 3 次行动）。
4. **组合式称号生成（需求 4）**：称号不再从单一池抽取，改为**结构 × 字段**两级
   概率生成：5 种结构（单核心 / 前缀+核心 / 核心+后缀 / 双核心 / 全结构，权重可配）
   × 10 前缀 × 12 核心 × 8 后缀；显示名按结构连接符拼接（如「孤高术士·候补」
   「刺客·退役」「剑圣·酒仙」），描述由各字段片段以「，」拼接成句
   （「生性孤高，禁忌术士，勉强候补。」）。
5. **移除元素克制（需求 5）**：删除克制矩阵与伤害计算中的元素乘数，元素仅作为
   身份标识展示（徽章/开场播报）；`elements.json` 相应简化。
6. **配套变更**：
   - 新增 locale 文件 `stats.json`（技能参数标签模板）与 `buffs.json`（buff 文案），
     每语言九个文件；
   - `battle_log.json` 的 `round_start` 模板改为 `tick_marker`，`battle_start`
     不再包含称号（HUD 已展示）；
   - UI 新增 `gauge_label`（行动）文案键，`summary_text` 改用 ticks；
   - PRNG 派生顺序更新为：稀有度 -> 元素 -> 属性 -> 技能数 -> 技能 -> 称号结构 ->
     称号字段（AGENTS.md 2.1.5 已同步）。

## 对确定性的影响

- **breaking**：同名对战结果与 v0.1.0 不同（战斗模型、技能参数、称号体系全部变更）。
  「同名同命」契约本身不受影响：新版本下名字 + 配置不变 ⇒ 结果依然永远不变
  （测试全部通过验证）。
- 技能个性化使用独立种子 `md5(name:skill_id)`，与主派生流解耦：向技能池增删条目
  不会影响其他技能的个性化结果。
