# v3.3.1 层数上限语义 + 描述一致性审计修复

日期：2026-09-01 ｜ 版本：3.3.1 ｜ 性质：**修复（非 breaking：同名对战结果不变）**

## 变更

### 1. max_stacks 语义修正（用户裁决：一切以描述为准）

原约定「0 = 不限」反直觉且在编辑器中显示为误导性的 0。新语义：

| 取值 | 含义 |
| --- | --- |
| -1 / 缺省 | 不限层数 |
| 0 | **禁用**（状态无法施加，不留运行时容器） |
| 1 | 可施加但不可叠层（单层） |
| >1 | 封顶层数 |

- 优先级不变：施加参数（含 params 规格默认值）> 状态定义顶层值；
- 引擎新增 `_stack_cap`（battle.py），施加与 status_ctl 两处统一取用；
- 现行配置无任何 0 / -1 值（破甲 3、乘胜 5 走施加参数默认，大器晚成缺省不限），
  故对战结果不变；
- 编辑器：max_stacks 改为可清空文本输入（留空即删除字段），标签注明「仅 count」，
  并提示 params 优先级；/api/schema 默认值改报 -1。

### 2. 不屈意志「永不耗尽」核实与文案对齐

- 核实：`0.52 × pow(0.5, N)` 浮点恒正且 chance 判定为闭区间比较，
  **数学上永不归零**（next_float 可返回恰好 0，极小概率仍可能触发）——
  实现与「逐次减半」描述一致，无需改引擎；
- 文案矛盾修正：`will_used` 的 desc「已耗尽展示」→「已触发展示（重生概率
  逐次减半，永不归零）」；will 的 detail 补「永不归零」；
- 战报模板：will_trigger「生命回复**至** {heal}」→「生命**回复** {heal} 点」
  （{heal} 为实际回复量，按量回复而非置值），「概率衰减」→「概率减半」。

### 3. 全技能描述 vs 实现一致性审计（25 技能 + 18 状态 + 全部战报模板）

逐条比对的修复：

- **渲染坏损**：status_ctl 子句的 `{target_word}` 未映射、`{op}` 裸英文
  （乘胜清零曾显示「操控{target_word}乘胜：stacks -99」）→ 补目标词与
  操作词映射（ctl_extend/shorten/stacks/clear）；compare 常数右值去掉
  「常数」前缀（「≤ 常数 33%」→「≤ 33%」）；
- **措辞不通**：hp_mod 比例治疗「回复 28.00% 点生命」→ 新模板
  op_hp_mod_pct「回复最大生命 28.00% 的生命」；
- **描述缺漏**：毒 / 破甲 / 撕裂的施加子句补「命中则」（攻击链上对敌方
  施加延迟到命中后生效，眩晕已如此表述而其余三个漏了）；
- **引擎钳制缺失**：`reflect_split_cap`（0.9，v2.0.0 提为配置）此前被加载
  却从未使用 → taken_mod 的减免比例现受其钳制（现行配置 0.18 < 0.9，
  结果不变）；
- **陈旧注释**：statuses.py 文档串与 status_display docstring 中已删除的
  reset_on_miss / lethal / `<id>_used` 展示残留清理；server.py schema 不再
  下发已删字段。

### 4. 编辑器样式修复

Windows 原生下拉弹层白底继承页面浅色文字导致白底白字不可读 →
select / option 显式实底（--bg-1）+ 浅色文字。
