# 更新记录 - v3.12.0（熟练度扩散映射 + 高基率重调：触发率波动拉满）

- 日期：2026-09-17
- 类型：feat（数值 + 引擎映射，**breaking**）
- 提交：`f4406cf`

## 变更内容

- **熟练度扩散映射（引擎）**：熟练度倍率换算前，投掷值先从中点 50 向外扩
  1.8 倍再钳回 [0,100]（`mult = lo + (hi−lo)×扩散值/100`）。原三角形分布
  集中于 50，多数实例挤在中间倍率；扩散后**中央 80% 的实例铺满几乎整个
  [0.25, 2.5] 区间**，两端 ~10% 实例落在端点。随机数消耗与顺序不变。
  Python（namefight/fighter.py）与 JS（web/js/engine/fighter.js）两侧同步。
- **高基率技能重调（配置）**：原 95% 基率的五个触顶技能（雷罚 36% / 疾影 37% /
  千锤百炼 33% / 乘胜追击 34% / 厚积薄发 35%）与其余 >0.55 基率的九个技能
  （×0.65，全局唯一取值：斩杀 43% / 淬毒 39% / 以牙还牙 31% / 燃血 45% /
  破甲 47% / 撕裂 41% / 孤注一掷 51% / 洞悉 55% / 血契 52%）——消除 95%
  上限压缩，让每个技能都有完整的低频~高频波动空间。
- `docs/GAME_SPEC.md` 同步（版本头 / 熟练度公式 / 触发率段落 / 14 行技能表）。

## 动机

- 用户需求：熟练度至少要影响实际 60% 的触发率、技能触发率波动要大。
  v3.11.0 只拉开了理论区间，但三角形分布集中在 50、高基率技能触顶 95%，
  实测波动仍被压缩。

## 对确定性的影响

- **breaking**：引擎映射与配置数值同时变更，改所有名字的技能数值与全部
  对战结果；随机数消耗顺序不变，同名结果依旧确定。JS 静态引擎已同步
  （差分 95 组 0 不一致），服务器 / Toy 两模式行为一致。

## 验证

- `python -m unittest discover -s tests`：**70 个测试全部通过**（基率唯一性
  防呆守卫触发后，五个触顶技能改为错开取值 33%~37%）。
- `node tools/port_check.mjs`（全量）：**95 组检查 0 不一致**（含新映射下
  的派生 / 全量战报 / 错误路径逐字节一致）。
- 波动实证（80 名字派生、143 个技能实例）：倍率分布 **p5=0.25 / 中位=1.46 /
  p95=2.50**（铺满全区间）；雷罚 9.0%~90.0%、重击 11.3%~68.6%、乘胜追击
  12.1%~85.0%、斩杀 29.5%~95.0%——熟练度对最终触发率的**波动贡献 69%~90%**
  （理论值 (2.5−0.25)/2.5 = 90%），满足「至少影响 60%」。
