## 变更内容

### 一、技能引擎四层解耦（全部 25 个现有技能覆盖，新技能不再需要改引擎代码）

1. **事件钩子层**（`namefight/effects.py` 注册表）：9 个执行时机——
   battle_start / action_interrupt / action_start / before_attack / on_attack /
   on_defend / on_hit_landed / on_hit_taken / after_action。
2. **条件系统**：8 种条件节点——chance / self_hp_below / self_hp_above /
   target_hp_below / target_hp_above / has_marker / no_marker / once_per_battle
   （阈值类参数统一为 `threshold`）。条件失败即跳过其下游子树。
3. **效果原语层**：23 个 op（`OPS` 注册表，含参数规格 ParamSpec：类型 /
   格式 / 钳制 / 量纲 / 可共鸣 / 熟练度可作用 / 枚举选项），复合原语全部拆分——
   壁垒 = damage_reduce + immune_chance 两节点；血契 = pact_cost + pact_convert；
   斩断 = gauge_delay + quick_strike；蓄力/雷罚/血契等引用状态的 op 显式声明
   `status_kind`，配置加载时校验兼容性。
4. **状态系统数据化**（`namefight/statuses.py`）：16 种状态按 16 个行为 kind
   （dot / control / shred / guard / momentum / grudge / record / lifesteal /
   regen / charge / will / tempo / boost / pact …）由通用容器承载（`st` +
   `markers`），定义（kind + 参数规格 + 事件模板 + 文案）全部移入
   `battle.json` 的 `statuses` 节；施加走 `_STATUS_APPLY` 按 kind 分发，
   结算点（防御 / 攻击 / 行动后 / 每刻）按 kind 迭代——**用户新建同 kind 状态
   （第二种毒、第二个怨念类叠层）无需改引擎**。

技能 JSON 新格式（图即数据）：

```json
"effect": {
  "nodes": [
    {"id": "n1", "kind": "trigger", "type": "on_attack"},
    {"id": "n2", "kind": "condition", "type": "chance", "params": {"chance": 0.14}, "pos": [280, 60]},
    {"id": "n3", "kind": "op", "type": "prepare_charge", "params": {"status": "charge", "value": 2.2, "crit": 0.25}, "pos": [560, 60]}
  ],
  "edges": [{"from": "n1", "to": "n2"}, {"from": "n2", "to": "n3"}]
}
```

`config.py` 做完整图校验（无环 / 无悬空 / 未知 op / 钩子不符 / 参数类型与
钳制逐参数校验）。派生层（`fighter.py`）的个性化（熟练度→value→damage→
前缀→后缀→共鸣槽）、共鸣、自然语言描述全部改为按注册表元数据组合生成，
`stats` 模板迁移为 hook_* / cond_* / op_* / st_* / lbl_* 词表。

### 二、引擎自描述 API

新增 `GET /api/schema`：返回钩子 / 条件 / op（含参数规格与 status_kind）/
状态 kind / 状态定义的注册表元数据——编辑器表单完全由 schema 驱动，
前端不再硬编码任何效果类型。

### 三、节点画布可视化编辑器（完全取代创意工坊）

- 新增 `web/editor.html` + `web/js/editor.js` + `web/css/editor.css`；
  **删除** workshop.html / workshop.js / workshop.css，导航指向 `/editor.html`。
- 技能页：SVG 贝塞尔连线 + DOM 节点画布（滚轮缩放 / 拖空白平移 / 节点拖动 /
  端口拖拽建边 / 点边删除 / Delete 删节点），左侧触发/条件/效果三类调色板，
  右侧 schema 驱动的类型化参数表单（状态引用参数渲染为按 kind 过滤的下拉框，
  可共鸣参数带 ⟡ 标记）。
- 其余五页签（属性 / 称号 / 战斗常数+状态定义 / 文案 / 系统）为结构化表单，
  全页签保留 JSON 源码模式逃生口；试运行（preview 打一场）与保存生效沿用
  现有 API。
- 顺手修复：`framework.js` 的 `NF.h` 现以 SVG 命名空间创建 svg/path 元素
  （此前 `createElement` 产生 XHTML 命名空间假 svg，连线永不渲染）。

### 四、顺手修复的怪癖（语义修正，均记为 breaking）

- **渐入佳境（tempo）** 触发率读取个性化值（原读原始 chance，个性化无效）；
- **孤注一掷（gamble）** 胜负判定使用独立参数，不再与触发 chance 双用；
- **破甲（shred）** 按刻到期自然消失（原先实际永不过期）；
- **报复（retribution）** 可被净化驱散（恢复 v1.x 行为）；
- **血契转化** 改为显式 after_action 钩子节点（自动转化逻辑删除）；
- 删除从未使用的 `effect_damage_up` 死模板；护盾叠层上限 0.75、反甲分流
  上限 0.9 提为 `battle.json` 常数（`guard_reduction_cap` /
  `reflect_split_cap`）。

## 动机

- 原引擎 10 处按效果类型的 if/elif 硬编码分发，加技能 = 改引擎，编辑器无法
  覆盖技能逻辑；解耦后**新增技能 / 新状态 / 调参数全部是纯配置操作**，
  节点画布即可可视化编辑一切。
- 状态文案原先在 battle.json 的 buffs 与技能参数双份同步，数据化后单一来源。

## 对确定性的影响

- **breaking：同名对战结果改变。** 确定性契约本身不变（同名同命、种子流水线、
  PRNG 消耗顺序 = 技能派生顺序 × 触发节点数组顺序 × 边数组顺序，均有测试守护），
  但技能图的节点 / 边顺序与部分怪癖修复改变了具体数值与随机消耗细节：
  - 怪癖修复清单见上（渐入佳境 / 孤注一掷 / 破甲 / 报复 / 血契）；
  - `skill.trigger` 顶层字段取消；复合原语拆分后条件判定顺序微调；
  - `buffs` 配置节并入 `statuses`；`variable_link.targets` 取消（共鸣资格
    改由参数规格的 `link` 标记声明）。
- 平衡漂移（重做后 300 场蒙特卡洛基线）：技能池胜率带 **41.4%–73.2%**
  （v1.3 基线约 45.5%–56.1%）。偏强：净化 73.2% / 震慑打击 67.3% /
  疾影 63.8% / 大器晚成 63.3%；偏弱：孤注一掷 / 报复 / 淬毒 / 铁壁约
  41%–42.5%；平局 0.27%，先手偏置 2.0%。**供后续纯配置调平衡参考**，
  引擎侧无问题。
