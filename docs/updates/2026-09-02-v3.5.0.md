# v3.5.0 审判每层独立数值 + 共鸣绑定可编辑 + 审判伤害上调

日期：2026-09-02 ｜ 版本：3.5.0 ｜ 性质：**breaking（审判伤害数值与每层结算
方式改变，同名对战结果改变）**

## 1. 审判标记：每层独立携带施加参数（语义修正）

用户指出：一个审判就是一种标记，**不同施加的审判不能叠在一起共用数值**——
它们的结算回合与伤害可能都不同。原实现 layers 模式只记录每层到期刻，伤害值
读共享的 `st["params"]`（最后一次施加覆盖前面的），共鸣使每次施加的数值都
可能不同时会算错。

- layers 条目从「到期刻」升级为 **[到期刻, 施加参数快照]**；
- on_status_expire 逐层触发时以该层快照构建求值上下文（`$value` 等取该层
  施加时刻结算的数值）；
- 全部触点同步：施加 / live 过滤 / 显示剩余刻 / status_ctl 延长与缩短（平移
  不改快照）/ 驱散清空；
- 隔离冒烟实证（共鸣随机槽关闭、仅覆盖表绑定 value↔自身攻击、大器晚成
  供攻击成长）：同一持有者的落雷伤害随施加时攻击递增变化
  （1956 → 1961 → 1971 → …），不再被最后一次施加覆盖；双跑一致。

## 2. 共鸣绑定可编辑（resonance 覆盖表）

「哪个属性可共鸣」此前纯随机（25% 概率 → 抽模式 → 抽变量 → 抽倍率），
现在可在编辑器里固定：

- 技能级可选字段 `resonance: [{node?, param, variable, mode, rate}]`：
  声明的参数固定绑定（不掷概率、不抽变量、倍率给定）；`node` 精确锚定节点
  （洗礼图中 n2/n3/n4 都叫 value，必须锚定 n4 才是审判伤害），缺省匹配图内
  首个该名可共鸣参数；未声明的照旧随机，覆盖与随机共享 max_slots；
- config.py 校验：param/variable 必填、rate ∈ (0,1]、node 必须存在、
  variable 必须在 variable_link.variables 定义、mode 合法；
- 编辑器技能面板新增「共鸣绑定（覆盖随机抽取）」区块：按节点逐候选参数
  下拉（随机 / 攻防速命暴闪六属性），绑定后出现模式与倍率编辑；
- 修复连带 bug：属性面板局部重绘（renderInspectorOnly）不拍平嵌套数组段，
  共鸣区块返回数组时 appendChild 抛错导致面板渲染中断——现与整页渲染
  （NF.h 自动拍平）同样处理；
- 派生保持纯函数：无覆盖表的技能代码路径不变、结果不变。
